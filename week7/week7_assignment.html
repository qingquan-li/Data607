Introduction

The goal of this assignment is to practice creating and reading two common data exchange formats – HTML and JSON – and loading them into R data frames.

I selected three well-known books in the DevOps domain: The Phoenix Project, The Unicorn Project, and The DevOps Handbook. For each book I recorded the title, authors, publication year, publisher, and ISBN. At least one of these books (The DevOps Handbook) has multiple authors, satisfying the assignment requirement.

My approach is straightforward:

  1. Create books.html with a simple HTML table and books.json with a JSON array, both containing the same data.
  2. Use the rvest package to parse the HTML table and the jsonlite package to parse the JSON file, loading each into its own data frame.
  3. Compare the two data frames to check whether they are identical.
library(rvest)
library(jsonlite)
library(dplyr)
library(knitr)

Solution

1 – Load the HTML data

The rvest package makes it easy to read an HTML table directly into a data frame with read_html() and html_table().

html_raw <- read_html("books.html")

df_html <- html_raw |>
  html_table() |>
  _[[1]]            # extract the first (and only) table

# Ensure Year is integer for a fair comparison later
df_html$Year <- as.integer(df_html$Year)

kable(df_html, caption = "Books loaded from HTML")

2 – Load the JSON data

The jsonlite package converts a JSON array of objects into a data frame with fromJSON().

df_json <- fromJSON("books.json")

3 – Compare the two data frames

We can check structural equality with all.equal() and exact equality with the identical() function.

If the two are not perfectly identical(), it is often because rvest returns a tibble while jsonlite returns a plain data frame, or because column types differ slightly. We can reconcile this:

# Convert both to plain data frames with matching types
df_html_plain <- as.data.frame(df_html, stringsAsFactors = FALSE)
df_json_plain <- as.data.frame(df_json, stringsAsFactors = FALSE)

# Ensure Year is integer in both
df_html_plain$Year <- as.integer(df_html_plain$Year)
df_json_plain$Year <- as.integer(df_json_plain$Year)

cat("identical() after normalization:", identical(df_html_plain, df_json_plain), "\n")
identical() after normalization: TRUE

Conclusion

Both files were loaded successfully and, after normalizing the data frame class and column types, the two data frames turned out to be identical. This confirms that the same information was faithfully represented in both HTML and JSON formats.

A few observations from this exercise:

  • HTML tables are display-oriented. Every cell is stored as character text, so numeric columns such as Year must be explicitly cast after import. rvest::html_table() returns a tibble by default, which can cause minor differences when comparing against a plain data frame.
  • JSON preserves types better. Because JSON distinguishes between strings and numbers natively, jsonlite::fromJSON() automatically read Year as an integer without any extra conversion on our part.
  • identical() is strict. Even when the underlying data match perfectly, small structural differences (tibble vs. data frame, integer vs. double) will cause identical() to return FALSE. Using all.equal() first is a helpful diagnostic step before forcing an exact comparison.

Overall, this assignment reinforced the importance of understanding how different file formats encode data and how R packages translate those encodings into data frames.
